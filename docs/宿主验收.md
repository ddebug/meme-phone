# 真实酒馆宿主验收

离线 `preview.html` 只能验"画得对不对"，验不了"装进酒馆后能不能用"。这份文档记录真实宿主的验收方法、踩过的坑，以及因此抓到的缺陷。

## 宿主环境

- 路径 `C:\Users\yona\Downloads\SillyTavern\SillyTavern`（v1.18.0），`node server.js` 起在 `127.0.0.1:8000`。
- 扩展目录 `public/scripts/extensions/third-party/meme-phone` 是 **junction**，Target 指向工作仓库，所以改代码即时生效、不用拷贝。
- 启动日志里能确认扩展被加载（`{ type: 'global', name: 'third-party/meme-phone' }`），启动时即读取并回写 `data/default-user/user/files/meme-phone.json`。
- 当前真实用户是 `default-user`：98 个角色卡文件（接口返回 69 张有效卡）/ 255 份聊天 / 84 本世界书。手机存档是信封格式 `{format:"meme-phone", revision, meme}`，内部 `contacts/chats/characters` 为空、只有 16 个 `users`——装了但没往里加角色。

## 为什么 headless 打真实站会"卡死"

不是扩展的问题，是宿主启动时会去外网取东西：

- `raw.githubusercontent.com/.../manifest.json`（第三方扩展清单）
- `huggingface.co/Xenova/t5-small/.../tokenizer.json`（本地向量化模型）
- 还有 `blob:` 资源

这些请求在本机**一直挂着不返回**（20s 仍是 `status=none`）。后果有两个：

1. `msedge --headless --screenshot` 要等"网络空闲"才截图 → 永远等不到 → 进程不退（之前残留的一批 msedge 就是）。
2. 宿主的初始化流程被 `await` 拖住，`app_ready` 迟迟不发 → 扩展的入口按钮和小手机挂不出来。

**解法**：用 CDP 接管页面，先 `Network.setBlockedURLs` 把这两个域直接阻断让请求快速失败，再导航。页面 4s 内就能跑到"扩展入口就绪"。

## 一条命令验完

```powershell
# 宿主要先起好：在 SillyTavern 目录 node server.js
npm run host-check
# 需要看图时加截图，或临时保留 Edge 进程
npm run host-check -- --shot=host.png --keep
```

脚本自启一个 headless Edge（独立 profile，不碰你正在用的浏览器窗口），阻断外网后依次断言：

| 检查 | 含义 |
| --- | --- |
| 宿主加载出扩展入口 | 等 `#meme-phone-qr-button` 出现，说明扩展在宿主里跑起来了 |
| 挂载 `#meme-phone` 与 `.mp-device` | 点「召唤手机」后外壳真的建出来 |
| 手机整体居中 | `.mp-device` 的中心与视口中心重叠（±2px），防 `fixed` 包含块塌陷复发 |
| 敲四行字整机尺寸不变 | 在宿主 `#send_textarea` 输入四行，前后 `.mp-device` 尺寸必须一致 |
| 点 dock 进聊天页 | `view=app-chat` |

当前结果：**5/5 通过**（视口 520×1000，手机 390×844，top=78、left=65，输入框从 1 行涨到 84px 时手机尺寸不变）。

## 因此抓到的两个真实缺陷

**1. `/api/settings/get` 的字符串信封**（提交 `f014fb4`）

该接口返回 `{ settings: "<settings.json 原文字符串>", world_names, ... }`，不是铺平对象。扩展两处兜底按 `saved.world_info_settings` 取值恒为空，导致**角色卡附加世界书（`charLore.extraBooks`）在真实宿主里永远读不到**；而 `getContext()` 并不暴露 `getWorldInfoSettings`，这条兜底是唯一路径。新增 `savedSettingsObject()` 统一解字符串信封。

**2. `.mp-overlay` 的 fixed 包含块塌陷**

宿主给 `<html>` 留了 `transform: matrix(1,0,0,1,0,0)`（identity 也算），且 `html` 高度为 0。于是 `.mp-overlay` 的 `position: fixed; inset: 0` 不再以视口为包含块，高度被压成几十像素，手机整体向上溢出视口（实测 `top=-398`，只剩中间一截可见）。预览页没有这个 transform，所以离线比对一直是 0px，完全看不出来。

改法是换成视口单位，不依赖包含块：

```css
.mp-overlay {
  position: fixed;
  top: 0; left: 0;
  width: 100vw;
  height: 100vh;
  height: 100dvh;
  box-sizing: border-box;
}
```

修完预览页 24 张比对仍全 0px（等价改动），真实宿主里 `top` 回到 78（正好居中）。

**3. 打字弹起软键盘时整机被等比缩小（#31 复发）**

`deviceScale()` 原先实时读 `window.innerHeight` 算等比缩放。软键盘/触摸键盘弹起时，布局视口高度在 resize 模式下会被临时压缩，`(vh-48)/844` 随之变小 → 整机在打字中途缩成一小条；键盘收起后又弹回。#31 当时只把 `visualViewport.height` 换成 `innerHeight`，以为后者不随键盘变，实际 resize 模式下它同样收缩。

改法是把**缩放基准视口**与打字期的可视抖动解耦：

- 打开手机时记下基准 `baseViewport`，`deviceScale()` 只按基准算，不直接读实时视口。
- 新增纯函数 `viewportForScale(base, next, typing)`：聚焦输入控件（`typing=true`）期间保留基准，失焦后才采纳新视口；真实拖窗口 / 旋转照常响应。
- `focusin` / `input` 置 `typing=true`，`focusout` 置 `false`，并在失焦后延迟一帧按真实窗口刷新基准；`visualViewport.resize` 一并纳入监听，销毁时移除。

行为验证（preview + CDP 压矮视口模拟键盘）：聚焦中把高度从 900 压到 520，scale 保持 0.98、整机不缩；失焦后才按 520 缩到 0.559；恢复 900 回弹 0.98。单测见 `tests/device-scale.test.mjs`。

**4. 手机等窄视口下整机天生小一圈（桌面仿真手机缩放残留）**

前三轮都在处理"打字弹键盘压矮高度导致误缩"，但真机在 iPhone 套壳里一打开就偏小。根因是这套界面本按"桌面浏览器里悬浮一台仿真手机"设计：整机固定 390×844，再由 JS `transform: scale(computeDeviceScale())` 等比缩小，代码里没有任何移动端排布分支。旧口径下标准 iPhone 视口静态缩放只有 0.73–0.88（375×667→0.733、390×844→0.877），即便不打字、不弹键盘，整机也比屏幕小一圈、四周留边。

试过"窄屏铺满整机"（`275b247`）后按真机反馈改回：**手机竖屏不铺满、宽度只由屏宽决定，软键盘顶上来只缩短高度**，输入区尺寸不动。

- 纯函数 `isMobileViewport(vw, vh)`：宽 ≤768px 且竖着的视口才算手机竖屏；宽屏与横屏仍走桌面等比缩放。
- 纯函数 `deviceLayout(vw, vh, availH, mobile)`：手机竖屏的 scale 只取宽度项 `(vw-16)/410`（410 = 390 内容宽 + 20 padding），clamp 0.45–1；高度在 `availH`（键盘剩下的可视高度）内缩短，宽度项完全不参与计算，所以键盘弹起前后宽度一致。桌面分支仍返回 `computeDeviceScale()` 与固定 844。
- `shell.js`：`visualBox()` 读 `visualViewport` 矩形，浮层贴住当前可视区（键盘弹起时高度就是键盘上方那块）；`applyLayout()` 统一写浮层 top/left/width/height 与整机 `height` + `transform`；`resize`、`visualViewport resize/scroll`、聚焦后 260ms 都各重排一次，兜住 iOS 不发 resize 的情况。
- `shell-03.css`：窄屏 `@media (max-width: 768px)` 只去掉浮层外边距；`.mp-device` 加 `flex: 0 0 auto`，否则会作为 flex item 被压窄（曾实测 390 内容宽被压成 370）。
- 移除 `apps-28.css` 旧的 `@media (max-width: 460px)` 外壳限宽 / 限高 / 圆角规则：那条按 `100vw - 20px` 改宽度，和"宽度只由屏宽决定"冲突；同段内气泡 `max-width`、钱包字号等内部适配保留。

行为验证（preview + CDP 模拟键盘把可视高度 844 压到 508）：390×844 下整机 374×788、scale 0.912；压到 508 后整机 374×**492**、scale 仍 0.912，输入区 80、输入框 20 完全不变，消息区 601→305，整机底边 500 落在可视区 508 内。桌面回归 1280×900（410×864、scale 1）、1280×700（317×667、scale 0.773）与历史基线逐项一致。单测见 `tests/device-scale.test.mjs` 的 `deviceLayout` / `isMobileViewport` 用例。

## 顺带核对过的链路（都命中）

- `/api/characters/chats`：要传带 `.png` 的 `avatar_url`，返回 `file_name` / `last_mes`，与扩展读取口径一致。
- `/api/chats/get`：返回数组，首行是 metadata header，扩展已有 header 识别。
- `/api/worldinfo/get`：`{entries, originalData}`，条目字段与 `normalizeBookEntries` 假设一致。
- `/api/characters/all`：69 张有效卡 → 同步出 69 个联系人、无重名、二次同步新建 0（幂等）。
- 存档 normalize：信封内层 `normalize(normalize(x))` 深比较完全一致。
- 世界书写回：`getContext().saveWorldInfo(name, data, immediately=true)` 签名与宿主源码一致。

## 平行时空（酒馆聊天分支）的验收步骤

这一版不再是「小手机自己组装」，而是**把酒馆的 chat 临时换成分叉点之前的楼层，再让酒馆自己生成**。下面几步必须在一个真实的酒馆聊天文件上走：

1. 在酒馆打开一个已经有几轮的聊天（最好带柏宝书记忆），回到小手机点「平行时空」→ 左上角「+」：应直接以这个聊天建一场并进分支页，标题是默认的「角色 · 分叉 N」，标题栏带「平行时空」、副标题写「接在《聊天文件名》第 N 楼」。**标题和副标题里都不能出现 `SillyTavern` / `SillyTavern System`**；列表分组标题也必须是角色名（点名前请确认酒馆侧栏选中的是角色而不是空聊天）。
2. 分支页顶部那行应显示「第 N 楼 · 跟随酒馆（或 固定开场时的总结）」（记忆那部分按这一场的口径走）；点头像旁设置按钮或这一行本身进「这一场的设置」，能看到背景口径、记忆口径、额外指令与显示项，以及「跟到最新楼层 / 重新绑定 / 重说 / 清空 / 改名 / 删除」。
3. 拿一个**大聊天**（几十 MB 或几千轮）重复第 1 步：点「+」应立刻进分支页，不卡、不闪退；保存后关掉小手机重开，「平行时空」里这一场还在，存档体积不应因为这一场暴增（快照只存分叉点，不存楼层副本）。
4. 发一句：消息立刻落进这一场并开始生成（不需要点第二次纸飞机）；生成中把酒馆的聊天页翻出来看，界面短暂显示的是「分叉点之前的楼层 + 分支」的临时历史，生成结束应回到你原来的聊天（消息数、最后一句都原样）。
5. 生成完点「看提示词」：应列出这次真正发给接口的 messages（system / 历史 / 本轮），条数和酒馆 Prompt Manager 里的口径一致。
6. 关掉小手机回到酒馆刷新：那个聊天文件**不应该**多出分支里的任何一句；分支只在「平行时空」里，不进聊天列表、不加未读。
7. 有柏宝书时：分支的回复应接着柏宝书总结里的时间/状态往下走（例如提到总结里出现过的地点）；柏宝书自己的记忆列表不应多出分支里的内容。
8. 切到**另一个聊天文件**再回这一场发一句：应提示「这一场绑的是另一个聊天文件，先在酒馆打开它再发」，不会拿别的聊天顶替，也不写脏数据。
9. 让酒馆接口故意失败（把 API Key 改错或断开网络）再发一条：这一场应留一条失败提示，旁边给「重试 / 撤回这句」；点重试不会再堆一句用户消息，点撤回只弹掉最后那一条；酒馆原聊天仍保持原样。
10. 长按卡片或分支页右上角：只有「这一场的设置 / 打开这一场 / 删掉这一场」；删掉后酒馆聊天、角色卡、柏宝书总结都不动。
11. 进「这一场的设置」：把「从哪里接」改成「最近一段」填 5 层，发一句后看提示词——应只带酒馆最近 5 层，分叉点之前的旧楼层不再出现；改成「不带背景」再发一句，提示词里只剩这一场自己说的话。
12. 把「记忆口径」改成「固定开场时的总结」（没读到总结时点「读一下酒馆现在的记忆」先补一份）：在酒馆里继续聊几轮再回这一场发一句，看提示词里应带着开场那份总结，而不是酒馆新聊出来的内容。
13. 在「额外指令」里写一句「这一场里他不知道那件事」：发一句，提示词末尾应出现这段原文；清空这段后提示词回到没有额外指令的样子。
14. 关掉「显示时间」「显示头像」：气泡下面的时间与头像应消失，只留气泡；再打开恢复。
15. 在酒馆里删掉几层导致「接不上的第 N 楼」时发送：应提示层数对不上；进设置点「跟到酒馆最新楼层」再发，应恢复正常。
16. 两场同时发：先在 A 场发一句、不等它生成完就去 B 场发——B 场应直接提示「另一场还在生成」，A 场生成完仍正常落回 A；A 场生成中途关掉小手机再打开，A 场不应因为界面销毁而报错，酒馆聊天也应原样。

## 原生链路不发酒馆预设的验收步骤

聊天、日记整理、主动消息、查 TA 手机这些手机原生链路，借酒馆当前模型时只发手机自己组装好的 messages；酒馆预设、角色卡、世界书、酒馆历史都不该进来。只有平行时空分支走酒馆自己的 `generateQuietPrompt`。

1. 接口预设选「酒馆 API」，在普通聊天里发一句，再整理一天日记：在酒馆 Prompt Manager / 接口日志里核对发给模型的 messages，应只有手机组装的系统条目 + 当天手机聊天，看不到酒馆预设正文、角色卡描述、世界书条目和酒馆历史楼层。
2. 平行时空分支里发一句：这一条仍然由酒馆自己组装上下文（预设 / 角色卡 / 世界书 / 记忆都走酒馆那套），与上面的口径不同，属于预期。
3. 自定义接口预设下失败 / 空返回仍直接报错，不静默退回酒馆模型。

## 心理活动与潜台词的验收步骤

协议条目在预设里，解析在 `parseBehaviorReply`，所以验收先看预设、再看两种入口：

1. 打开「回复预设」页：应该能看到固定条目「心理活动与潜台词」，内容里写明 `[心里]` / `[潜台词]` 各自贴在上一个气泡下面；这条不能删。
2. 让 TA 回一轮（真实接口或演示模式都行）：打开这条回复的请求调试预览，拼进去的 system 条目里应包含这段说明。
3. 回归复一条带心理活动的消息：气泡旁边头像上有一粒小点；点头像弹出「<角色> · 这一条背后」，里面有心理活动原文，有潜台词时一起列出，并给出「这条的小剧场 / 存成小剧场」两个动作。
4. 有潜台词的消息，气泡上方或下方应出现「潜台词」小眼睛：点开后气泡下面展开一层半透明文字，再点收起；关掉重开这一页默认是收着的（开关不写存档）。
5. 长按这条消息：多出「看 TA 的心理活动」「看这条的潜台词」两项，点了分别打开面板 / 展开标注。
6. 对这条点「让 TA 重新说一次」：旧的心理活动和潜台词应随这一轮一起被替换，不会残留到新气泡上；撤回这条消息时，两层含义一起清掉。

## 换角色头像的验收步骤

1. 打开通讯录 → 点一个酒馆角色进资料页：头像右下角应有一枚深色小相机角标；点头像弹出「换『<角色名>』的头像」。
2. 选「从相册里选一张」：选一张横图，确认头像变成居中的方形裁切（不该被拉扁），聊天页头像、消息气泡头像、会话头一起变。
3. 选「用回酒馆里的头像」：头像应回到角色卡当前那张；再进一次「更多」菜单应该有同样的换头像入口。
4. 回到酒馆宿主里刷新一次、重新同步角色（比如点设置里的同步或直接刷新扩展）：自定义头像不能被角色卡的原图顶掉，联系人的关联与名字则照常更新。
5. 刷新页面 / 重新打开扩展：头像仍在；把存档备份导出再导入，头像也应该原样回来。
6. 确认酒馆那边的角色卡头像没有被改动（小手机只改自己这份显示）。

## 单角色聊天导出 / 导入带日记的验收步骤

1. 进一个有聊天记录、也整理过几天日记的角色会话：聊天设置里点「导出这段聊天」，下载的 JSON 里除 `messages` 外应有 `diary` 数组，`diaryCount` 与条数一致；每篇日记带日期、正文、标签、自动/手动、是否切回原文和指纹 / 时间范围等字段。
2. 全局日记（Dock 里不挂角色的那部分）不进这个单角色导出包；别的角色的日记也不混入。
3. 把这份 JSON 导入到另一个会话（或清掉本地后导入）：消息按 ID 合并、日记按日期补上；已经存在的日期日记保持本地旧正文，不被导入内容覆盖。
4. 导入后打开该角色日记页：新补的日记正文、标签和「切回原文」标记都在；只含日记没有消息的包也能导入，只含消息的旧版包按空日记兼容。

## 进会话自动落到最新一条的验收步骤

1. 找一段消息较多的会话，从桌面主页点「最近聊天」小组件直接进入：打开后应停在最新一条（输入框上方就是最后一条消息），不需要手动往下翻。
2. 从聊天列表点进同一段会话、以及从同层小手机列表进会话，同样应落在最新一条。
3. 进会话后先往上翻到中间，再进「聊天设置」或角色日记页、或点开一张消息大图，返回会话后应停在刚才翻看的位置，不被强制拉到底。
4. 会话页内重绘（展开潜台词、开关调试栏等）不改变当前滚动位置。

## 唤起软键盘不闪页的验收步骤（RB-14）

1. 手机端打开小手机，点进会话点输入框唤起软键盘：整机 / 浮层不应来回缩放或上下跳一下，消息区与输入框保持稳定。
2. 键盘弹起期间宿主酒馆页面不跟着回弹、不被顶走；收起键盘关闭小手机后，宿主页面原来的滚动位置、`body` 滚动状态与 viewport 声明恢复原样。
3. 打字过程中重绘（如发送、展开潜台词）后焦点恢复到输入框，宿主页面不被滚动带动。
4. 离线基线回归：390×844 / 375×667 / 430×932 窄屏与 1280×900 / 1280×700 桌面的整机尺寸、缩放与历史基线逐项一致；键盘把可视高度从 844 压到 508 时宽度与缩放不变、高度单调缩短，无来回抖动。
