# 聊天预设完整移植方案

参考源：`acsus-phone-standalone/toolkit/phone/settings/preset-settings-ui.js`
目标：`meme-phone/meme/apps/presets.js`、`meme/data.js`、`meme/preset-defaults.js`

## 一、结论

1. 保留 meme 的多套回复预设，不退回单套。参考项目的单套预设 = meme 的其中一套预设。
2. 参考项目默认 24 条全部进入 meme 的默认条目集合；另外保留 meme 已有的世界书、酒馆记忆、场景三条上下文，共 28 条。每套内置预设再带一条「回复指令」普通条目，默认排在 QQ 聊天行为要求之后，实际显示 29 条；`defaultReplyItems()` 仍保持 28 条默认集合。
3. 功能按参考项目补齐：拖拽排序、列表页导入 / 导出、单套预设导入、恢复默认条目。编辑、添加、删除、开关、上下文配置、预算、预览继续沿用现有实现。
4. 页面沿用 meme 现有的页面内编辑，不引入参考项目的 popup，也不引入 jQuery UI Sortable。
5. 依赖 acsus 消息协议、但 meme 当前没有解析链的条目保留原文，默认关闭，并在条目副标题标记“原版条目 · 当前手机未接入”。

## 二、数据映射

### 直接保留为静态条目

头部、QQ 聊天任务、QQ 聊天行为要求、手机相关记录、收藏夹消息、约定计划、修改个性签名、戳一戳、撤回、引用、转账、会员、关注消息细节、用户当前操作提醒、本轮任务清单、中文回复、尾部。

### 映射为 meme 上下文

| 参考条目 | meme 条目 | 现有能力 |
| --- | --- | --- |
| 用户角色设定 | `reply_context_user` | 读当前酒馆人设 |
| 个签历史 | `reply_context_signature`（新增） | 当前用户签名；无历史回退 |
| 角色档案 | `reply_context_character` | 角色卡 description / personality |
| 表情包库 | `reply_context_emoji`（新增） | 读 `state.emoji` 表情名称与符号 |
| QQ 聊天记录 | `reply_context_history` | 当前会话最近 N 条 |
| 时间信息 | `reply_context_time` | 当前日期、星期、时间；无天气 |
| 世界书 / 酒馆记忆 / 场景 | 原有三条上下文 | meme 独有，保留 |

参考项目的 `char-info` 还包含历史记录、线下剧情，meme 的角色卡读取面较窄，只能做到 description / personality；其余内容不会伪造。

### 参考格式条目的处理

参考项目 `回复格式要求` 使用 `[角色-角色名]` + `[消息]` 的多角色 QQ 协议。meme 当前生成入口只返回一条纯文本，直接启用会让聊天显示原始标签。

处理方式：

- 现有 `reply_item_format` 继续使用 meme 的单条消息格式，作为默认开启条目。
- 参考项目原文以 `reply_item_qq_format` 保留，默认关闭。
- `尾部` 原文保留；其中“正确格式”按当前启用的格式条目理解。

## 四、页面与交互

### 列表页

- 顶部改为紧凑导航：返回、导入、导出、新建。
- 导入改为页面内联确认，不再走弹窗式 sheet：
  - 多套格式：覆盖现有预设，显示将被覆盖的数量。
  - 参考项目的 `{ items: [...] }` 单套格式：导入为一套新预设，不覆盖现有预设。
- 导出仍导出整套预设备份。
- 新建保持内联输入。

### 详情页

- 「回复指令」不再作为单独的置顶字段；它是一条普通聊天条目，默认插在 QQ 聊天行为要求之后，和其余条目一样可编辑、开关、删除、拖动排序。
- 条目左侧增加拖拽手柄，按住拖动排序；松手后写入 `order` 并保存。
- 右侧操作收敛为“删除 / 开关”，去掉上移、下移两个占位按钮。
- 删除仍保留一行隐藏占位，保证没有删除按钮的条目开关仍然对齐。
- 详情页导航保留恢复默认条目和删除预设；增加“导出当前预设”，输出参考项目可识别的单套 JSON。
- 恢复默认条目恢复完整的 28 条默认集合，并恢复上下文开关默认值；当前「回复指令」条目保留原内容和位置。

### 分组

- 分组不是按类型集中，而是按上下文的真实 `order` 切成「连续位置块」：同一组只覆盖一段相邻条目。
- 中间夹了别组条目时，后续同组条目自动生成 `group_xxx_p1`、`_p2` 等新块，绝不把不同位置的条目强行并进同一组。
- 组头显示 `N 条 · 位置 X–Y`；空的其他软件组显示 `0 条 · 未使用` 并留在列表末尾，方便继续加 app 条目。
- 顶部「新建分组」要选「从这一条开始 / 到这一条结束」，只给这段连续条目换组名，不移动条目。
- 点组名可改名；删除分组前二次确认，条目位置不变，只并入相邻的上一组或下一组；空组直接删、不动条目。
- 每组右侧加号把新条目加在该位置块末尾（组内最大 `order + 0.5`），保证仍落在这一段连续位置内。
- 组内拖拽只在该位置块内重排并写回全局 `order`；其他位置块和条目的相对位置不变。

### 不改的部分

- 多套预设的增删改、设为手机默认。
- 单聊单独选择回复预设。
- 上下文配置、预算、实际注入预览。
- API、记忆、消息解析、酒馆读取。

## 五、兼容与迁移

- `normalizeReplyItems` 继续自动补上下文，最大列表容量维持现有逻辑；新增 `signature`、`emoji` 两类，老预设升级后会自动补上。
- 只保留内置「自然发消息」一套；旧版的 `reply_short / reply_soft` 首次加载时移除，若 `activeId` 指向它们会回退到自然发消息。`reply_natural` 条目仍是旧的 13 条默认集合时升级为 28 条完整默认；用户自建预设不动。
- 旧预设顶层的 `text`（回复指令）首次读取时迁入普通条目 `reply_item_main`，随后清空顶层 `text`；旧数据不会出现两份指令，新数据也不再依赖这个独立字段。
- 新增可选字段 `note`，只用于条目副标题说明“未接入”，不参与模型请求。
- 新增 `preset.groups`（`{ id, name, kind }`）和 `item.group`；旧预设没有 `groups` 时回退默认三组，按 `kind` 自动归组；保存后 `item.group` 指向连续位置块，块 id 允许 `_pN` 后缀；导出、导入、新建副本都会带上分组。
- 导出保留 `text`、`context`、`groups`、`items`；导入兼容 `presets`、`reply.presets`、`items` 三种形状；旧式带 `text` 的单套导入同样会迁进条目。

## 六、验收

1. `node scripts/check.mjs` 通过。
2. `node scripts/test-context.mjs` 通过。
3. `python scripts/build_preview.py` 重建预览。
4. 预设详情出现 29 条（28 条默认集合 + 回复指令普通条目）、可滚动、拖拽排序后刷新顺序保持。
5. 13 个以上开关在同一 x 坐标，1400px 宽手机不横向溢出。
6. 导入参考项目单套 JSON 后生成一套新预设，条目不少于 24 条。
7. 默认主题、frost、像素小兔日夜模式无错位。
8. 旧预设自动补三组；组头位置区间与实际 `order` 一致；跨位置同组会拆块；按范围新建、改名、删除分组后条目位置不变。
