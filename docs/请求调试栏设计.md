# 聊天请求调试栏 · 设计

## 一、目标

在聊天会话页的输入栏上方加一条只读的请求调试栏：

- 收起时显示这一轮**预计发送的 token 数**（`≈ 1,284 tk`）。
- 点开后在当前页内联展示这一轮请求的构成：消息条数、角色、来源、每条 token / 字数、实际内容预览。
- 同时展示因关闭、重复、超预算而没有进入请求的条目及原因。
- 设置里提供开关，关掉后整条调试栏不渲染。

调试栏只观察、不改写请求；实际发送仍然走原来的 `buildReplyMessages` + `generate` 链路。

## 二、信息架构

```
┌ 会话页 ─────────────────────────────┐
│ 消息列表                             │
│                                      │
│ ┌ 请求预览   ≈ 1,284 tk  8 条  ⌄ ┐   │  ← 收起态，单行
│ │ 总计 ≈ 1,284 tk · 8 条消息       │   │
│ │ 接口：OpenAI · gpt-4o-mini       │   │
│ │ ████████░░░░ 规则 / 设定 / 对话   │   │  ← 份额条
│ │ 规则 · 回复要求      系统  312 tk │   │
│ │ 设定 · 角色档案      系统  486 tk │   │
│ │ ...                              │   │
│ │ 未进入这一次 · 3 条              │   │
│ │ 按字符估算，实际以模型分词为准     │   │
│ └──────────────────────────────────┘   │
│ 空着发出去，TA 会主动开口              │
│ [+] [ 发消息… ] [发送]                │
└──────────────────────────────────────┘
```

- 调试栏放在 `.mp-composer` 最上方，位于提示语和输入行之前。
- 展开是“向上长高”：消息列表被压缩，输入行仍在底部；不弹窗、不跳新页。
- 展开面板本身可滚动，最大高度 `min(34vh, 280px)`；手机宽度下不横向溢出。
- 点栏头切换展开/收起；点消息行展开该条的完整内容（原生 `<details>`，不触发页面跳转）。

## 三、数据来源与性能

### 3.1 同一套组装

新增 `ctx.ai.preview(chat, contact)`：

- 内部调用与真实回复相同的 `buildReplyMessages`，只多传 `omitLastUser: true`，先组出“除最后一条用户消息以外的完整请求”。
- 聊天页拿到这份 base 后，根据当前输入框内容在本地补上最后一条：
  - 有输入：`用户：<草稿>`。
  - 输入为空且允许空发送：把“场景提示”换成主动开口的提示，并补上主动消息占位。
  - 输入为空且空发送关闭：不构造请求，显示“输入后统计”。
- 因此调试栏看到的来源、顺序、裁剪结果和真实发送一致，不会出现第二套组装逻辑。

### 3.2 缓存与刷新

- `preview` 结果按 `chatId + 消息条数 + 最后一条消息 id + 当前回复预设 / 接口 / 小剧场开关` 缓存 30 秒。
- 发消息、收到回复、切换会话后消息状态变化，key 自然失效并重建。
- 输入时只重算 token 与最后一条内容，不重复读记忆和世界书。
- 异步统计期间显示“统计中…”；失败显示“统计失败”，不阻塞发送。

### 3.3 token 估算

不引入新依赖。用本地轻量估算：

- 中文 / 日文 / 韩文 / 全角标点：约 1 字 1 token。
- 其他字符：约 4 字符 1 token，按连续片段向上取整。
- emoji 等代理对：约 2 token。
- 每条消息加 4 token 的角色与分隔开销。

界面统一带 `≈`，并在面板底部写明“按字符估算，实际以模型分词为准”。这是调试参考值，不冒充精确分词。

## 四、视觉规范

- 收起态高度 30px：左侧小标签「请求预览」，中间加粗 token 数，右侧展开箭头；消息条数放进展开面板，不在收起态重复。
- 展开态使用同一张卡片，不新增浮层；卡片圆角与输入框一致（18–20px），背景比输入框更淡。
- token 数字用等宽数字（`font-variant-numeric: tabular-nums`），强调但不抢发送按钮。
- 份额条使用低饱和色块：规则 / 设定 / 记录 / 本条 / 小剧场，每类颜色同时用于行首圆点，避免再放一遍图例。
- 行内信息分层：
  - 主行：来源 + 角色 + token。
  - 次行：内容摘要（单行截断）。
  - 展开后：完整内容 + 字数 / 角色。
- 未进入请求的条目降一级：灰色小字 + 原因，不参与份额条。
- 兼容：
  - 默认主题：浅紫底、深色字。
  - 磨砂：半透明白卡、细边。
  - 像素小兔：冷白纸、黑色硬边、硬投影。
  - 日间 / 夜间：全部走现有 CSS 变量，夜间单独补对比度。
- 展开 / 收起即时显示；只保留箭头和背景的轻微过渡，并尊重 `prefers-reduced-motion`。

## 五、状态与边界

| 状态 | 收起态 | 展开态 |
| --- | --- | --- |
| 统计中 | `请求预览 · 统计中…` | 显示“正在读这一轮的上下文…” |
| 有草稿 | `≈ N tk · M 条` | 完整构成 |
| 空输入 + 允许主动开口 | `主动开口 ≈ N tk` | 主动提示 + 占位消息 |
| 空输入 + 空发送关闭 | `输入后统计` | 基础上下文构成，标注“不会发送” |
| 统计失败 | `统计失败` | 失败原因，可重试 |
| 设置关闭 | 不渲染 | — |

其它：

- 小剧场开关打开时，请求里会出现来源为「小剧场」的 system 消息，调试栏照实显示。
- 重新生成（重说）不增加消息条数；预览以当前消息状态为准。
- 超长内容在行内截断，展开后完整显示；`overflow-wrap:anywhere` 防止横向溢出。
- 切换会话时旧预览不串台：按 chatId 校验。
- 调试栏不写入 `meme-phone.json` 的任何聊天数据；只读设置开关。

## 六、设置入口

设置 → 聊天：

```
请求调试栏
在输入框上方显示预计 token 与请求构成     [开关]
```

- 字段：`settings.chat.debugBar`，默认 `true`。
- 关闭后会话页不再渲染；重新打开立即恢复。
- 不新增独立设置页，不新增二级入口。

## 七、验收

- 开关关闭时完全看不到调试栏；打开后出现在输入栏上方。
- 有草稿时 token 数随输入变化；空输入时按是否允许主动开口显示不同模式。
- 展开面板列出每条消息的来源、角色、token、字数与内容；顺序与真实请求一致。
- 被关闭 / 重复 / 超预算的条目能说明为什么没进请求。
- 小剧场开启时出现「小剧场」来源。
- 不改变 `buildReplyMessages` 的默认返回；不改变 API 请求、模型测试、拉取模型、方案保存。
- 三套主题 × 日夜模式均正常，手机宽度无横向滚动。
- `node scripts/check.mjs`、`node scripts/test-context.mjs`、`python scripts/build_preview.py` 通过。

## 八、实现边界

- 设置页增加开关与字段归一化。
