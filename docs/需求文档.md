## 0. 一页结论

这套产品的主线可以概括为：

**把酒馆里的「小手机」从一个功能堆叠的复杂面板，重构成一台有桌面、有 App、有返回逻辑、数据独立的手机；聊天仍是核心，但 API、酒馆记忆、绘图、角色、日记、音乐、计划都要成为能单独进入的 App。**

截至当前代码基线：

- **已经落地**：桌面 + App 信息架构、毛玻璃视觉、透明壳外/不透明壳内壁纸、统一返回、User 管理、查角色、查 TA 的手机、世界书条目开关、角色日程、聊天设置、小剧场入口、日记、音乐、API 预设、绘图整体方案、酒馆记忆预设、记忆独立 App、LLM 整体方案、会员/收藏/钱包/旧酒馆总结的删除。
- **明确未完成或未迁移**：旧小手机导出配置导入、`meme-phone` 内的完整主动消息定时调度、调用调试/补录角色回复、会话级「API + 记忆」整体方案一键切换。
- **明确留白**：群聊成员管理、图片消息与查看器、转账流程（当前 README 已声明不做）。
- **只做过静态复核、未在真实宿主完整验收**：酒馆 User 写回、最新酒馆聊天读取、真实模型付费链路、移动端触控与多宿主兼容。
- **已知限制**：NovelAI 官方端点返回 zip，当前只解 JSON / 直出图片。

## 2. 产品定义

### 2.1 一句话定义

**运行在 SillyTavern / TauriTavern 里的手机形态前端扩展：以角色聊天为核心，以桌面 + App 为信息架构，数据独立存放，外观可换，能力可配置。**

### 2.2 目标用户与核心场景

- 用户在酒馆里和角色聊天，希望把聊天从酒馆原生界面里「拿出来」，变成一台有沉浸感的手机。
- 用户会同时管理多个角色、多个会话、多个 User 人设，需要一套能跟随酒馆、也能固定下来的身份系统。
- 用户会自己配置聊天 API、酒馆记忆、绘图 API 和提示词，不希望每次换模型都重新填地址和 Key。
- 用户会查看角色的世界书、角色手机、角色日程，用这些内容增强角色扮演，而不是只停留在聊天框。
- 用户会用日记、音乐、计划、小剧场等 App 让手机「像一个真实设备」，而不是一个换皮聊天窗。

### 2.3 非目标

- 不是独立运行的聊天网站，不包含酒馆后端。
- 不是离线后台服务；酒馆页面关闭、应用休眠或系统挂起后，不承诺继续主动消息。
- 当前 `meme-phone` 不实现群聊成员管理、图片消息与查看器、转账流程；这些入口不假装可用。
- 不复制旧项目代码、命名、存储文件；旧项目保持原样，等新界面对过之后再谈替换原前端。

## 3. 两代产品的关系

### 3.1 独立小手机（st-phone / Acsus Phone）

- 起点：原 `Acsus-Paws-Puffs` 2.0.0 里的 `toolkit/phone` 模块。
- 核心动作：把这个模块拆成可独立安装的酒馆前端扩展，独立存储、独立入口、独立菜单，不修改原插件。
- 主要能力：联系人、聊天、表情、收藏、手机 API/预设、约定计划、模拟钱包/会员、装扮、日记总结、三种主题、角色主动消息、角色小剧场、LLM 日志补录、空白纸飞机手动主动继续。
- 主要问题：功能多但入口复杂，三个标签页加一个隐藏加号菜单；聊天数据曾写在酒馆总配置里；界面偏旧，用户最终要求完全重构。

### 3.2 meme-phone

- 起点：2026-11-11，用户明确要求「完全重构界面」，先设计前端样式，不改原代码；界面确定后再替换。
- 核心动作：新建项目、复制原项目后直接改前端；新项目不出现 `acsus` 等旧名称，命名 `meme-phone`。
- 主要变化：从「标签页 + 加号菜单」改成「桌面 + App 图标 + Dock」；每个功能是一页；返回统一；数据写自己的文件；视觉改成可爱、清新、时尚、简约、毛玻璃。
- 关系：独立项目，不引用旧项目代码、命名或存储；旧项目保留。当前 `meme-phone` 是需求的主目标，旧版需求作为能力基线和历史契约继续参考。

### 3.3 关于「QQ 小手机」基线

用户在提「酒馆记忆预设」时，明确要求参考「本地那个 QQ 的小手机，最开始做的，让你新建文件夹重做的」。这里的重点是**聊天呈现与预设思路的基线**：逐条气泡、按角色分开、记忆来源可选；不等于当前 `meme-phone` 要复刻 QQ 皮肤。当前视觉仍以「可爱、清新、时尚、简约、毛玻璃」为准。

## 6. 验收标准

### 6.1 视觉与导航

- 打开手机，壳外必须直接看到酒馆页面，没有整块背景、没有壳外第二层背景。
- 壳内壁纸不透明；页面和消息区能透出壁纸但文字可读。
- 每个页面都有返回；返回上一页；栈底回桌面；没有重复的底部操作条。
- 切换主题立即生效；切页不闪；自定义壁纸不被主题切换冲掉。
- 桌面与 Dock 图标统一毛玻璃；不出现旧 Acsus 复刻图标。
- 桌面没有重复的「发消息 / 日记」小按钮行。

### 6.2 功能

- 聊天：发送、引用、复制、重新生成、删除、空输入唤醒、头像看小剧场、右上角进会话设置全部可用。
- 会话设置：LLM、酒馆记忆、日记、小剧场入口齐全；单独设置后实际生效；没设置跟随手机整体方案。
- 酒馆记忆：默认读角色最新聊天；有总结先注入总结；无总结才按层数注入原文；预设可新建/改名/来源/层数；记忆 App 可进入。
- 绘图：聊天与绘图接口分离；NovelAI / 豆包 / 自定义可选；整体方案能存、能切、能改名/复制/删除；豆包请求格式正确；出图参数与「再来一张」可用。
- 角色：User 同步/编辑/写回/跟随/固定；查角色只读；查 TA 的手机三 tab；世界书逐条开关；日程周/月/年。
- 音乐：网易云/汽水导入；歌单列表/详情/播放器/删除；导入失败有反馈；播放不了的歌自动换源、播放中断能续上、全都失败明确报「没找到」。
- 删除：会员、收藏、钱包、旧酒馆总结的入口/App/状态/图标/样式/残留字段全部清除。

### 6.3 数据与成本

- 写入后读回确认；失败不静默；不覆盖未确认数据。
- 导出默认不含密钥；导入前有备份；旧配置导入必须先预览、不直接覆盖。
- 自动主动消息/补录遵守配额、锁、免打扰、失败不重发规则。
- API Key 明文风险有提示；不把手机数据文件提交到 Git。

### 6.4 完成定义

一条需求只有在满足以下条件时才可标「已完成」：

1. 代码已落地并能从真实入口到达；
2. 真实数据被读写，不是演示占位；
3. 错误路径有反馈，不静默失败；
4. 删除类需求连残留字段/样式/入口一起清掉；
5. 若依赖真实宿主或付费模型，至少完成一次用户侧真机验证并记录结果；未验证的只能标「已实现，待实测」。

| 收藏/钱包/会员 | 原版保留 | 全部删除，连入口、状态、图标、样式、残留字段 | 用户明确说没用 |

| 换源的验收方式 | 旧约定是「不做浏览器验收」 | 这一次单独跑了一次无头 Edge + CDP 的真播放验收（4 组场景），只用于确认「真出声」，不常驻、不进 CI | 「有没有声音」静态复核证明不了；其余仍按老约定只做源码复核 |
| 测试方式 | 用户多次说不要测试 | 只做源码/语法/导入静态复核；不跑真实模型、不做浏览器触控验收 | 旧版工作约定延续到当前 |
