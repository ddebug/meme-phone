# 小剧场类型与美化页面方案

## 一、当前注入位置

1. `meme/index.js` 的 `compose()` 决定这一轮是否带小剧场，把写作提示词传给 `buildReplyMessages()`。
2. `meme/reply-context.js` 把提示词作为一条 `role: 'system'`、`source: '小剧场'` 的消息加入请求。
3. 本次把这条消息固定放在**全部回复预设条目之后、最后一条聊天之前**。这样不会被前面的聊天行为、格式要求覆盖，也仍然排在用户最后一句话之前。
4. 模型返回的 `<phone-extras>…</phone-extras>` 会在 `splitTheaterBlocks()` 中从聊天正文移除；聊天只显示正文，小剧场只进小剧场 App。

## 二、类型设计

类型是“这一轮请模型写哪一种小剧场”，不是另外发一次请求。当前先内置四种，后续可在同一张类型表继续加：

| id | 名称 | 写作方向 | 页面风格 |
| --- | --- | --- | --- |
| `daily` | 日常 | 日常切片、没说出口的情绪和小动作 | 暖色纸张 / 手记页 |
| `meta` | Meta | 跳出剧情吐槽叙事、设定和作者注，不冒充模型真实推理 | 深色终端 / 注释页 |
| `dream` | 幻想 | 梦境、意象、另一种可能的场景 | 星夜 / 浮层页 |
| `nsfw` | NSFW | 成年角色之间克制的亲密片段，只写情绪、气氛、关系张力和留白；不写露骨性行为、身体细节或具体动作 | 酒红丝绒 / 18+ 确认页 |

`nsfw` 是展示与氛围类型，不做露骨内容生成。列表和详情页都先显示 18+ 确认；未确认时正文模糊/隐藏，确认后才渲染。该类型仍遵守“不替用户决定言行”的原有边界。

## 三、数据模型

沿用现有 `extras` 结构，不新增单独数据库、不改聊天或记忆结构：

```js
{
  id, title, date, lines, messageId, chatId, at,
  kind: 'daily',          // 新增：类型 id
  sections: [             // 新增：保留原始分节，供美化页使用
    { title: '心理活动', content: '……' }
  ]
}
```

- `settings.theater.kind` 保存当前选择的类型，默认 `daily`。
- 旧条目没有 `kind`/`sections` 时按 `daily` 兼容：`lines` 继续用于列表摘要，详情页从 `lines` 还原分节。
- `theaterPrompt(contactName, kind)` 根据类型生成不同写作要求与分节标题。
- `addExtrasEntry()` 写入 `kind` 和 `sections`；不改变聊天消息、记忆或其他 App 数据结构。

## 四、页面与交互

### 小剧场开关页

- 顶部增加类型选择：日常 / Meta / 幻想 / NSFW，单选，当前类型高亮。
- 下面仍是按角色的开关列表和“全部打开”；开关只决定这一轮带不带，类型决定写哪一种。
- NSFW 类型选项带 `18+` 标记和说明。

### 小剧场 App 列表

- 列表顶部增加类型筛选：全部 / 日常 / Meta / 幻想 / NSFW。
- 每条卡片显示类型徽标和对应色条；没有类型的旧条目按日常显示。
- 卡片摘要不展示 NSFW 正文。

### 美化详情页

每个类型对应一个独立渲染模板，共用 `extra-detail` 路由：

- 日常：暖米色纸张、衬线大标题、编号分节、页脚日期。
- Meta：深墨绿/黑底、等宽标签、`META` 水印、分节像注释条目。
- 幻想：夜空渐变、星点、半透明浮层卡片、斜体引文。
- NSFW：酒红/近黑底、18+ 门页；未确认只显示标题和确认按钮，确认后显示正文；页面仍支持返回和滚动。

三套主题（默认 / frost / 像素小兔）和日夜模式都要正常；页面自身颜色只作用于详情页，不改变手机壳和全局主题。

## 五、兼容与边界

- 旧条目、旧导出数据不需要迁移字段；读取时补默认 `daily`。
- 类型选择只影响今后的生成，不改已有小剧场。
- 不把类型写进聊天正文，不把正文注入后续上下文。
- NSFW 不做露骨提示词、不做正文预览、不在列表直接展示；只做克制的氛围页。
- 不改 API、回复预设、记忆、酒馆读取链路。

## 六、聊天页加号小剧场弹窗

聊天输入栏下方的 `+` 不再把用户带去独立设置页，而是直接在当前聊天页打开「小剧场」面板：

- 顶部说明只控制当前角色这一轮是否带小剧场，以及写作类型。
- 「写哪种」展示全部四类（日常 / Meta / 幻想 / NSFW），点一下切换写作类型；NSFW 带 `18+` 标记。
- 下方只有当前角色的「这轮带小剧场」开关，不再列出通讯录所有角色，也不提供「全部角色」批量开关。
- 选择写作类型不会自动打开当前角色的开关；开关状态由用户单独控制，行内会显示「当前角色只聊天 / 会带 X 小剧场」。
- 开关即时写入本地状态，不弹确认框；类型切换和角色开关都复用现有 `settings.theater.kind` / `extrasOn`，不新增存储结构。
- 底部只保留「打开小剧场 App」文字入口和「完成」按钮；其他角色的管理仍走原有小剧场开关页，不在本弹窗重复。
- 面板使用通用 `panel` 弹层渲染，手机宽度正常；内容不显示小剧场正文，正文仍只在独立 App 的详情页查看。

## 七、验收

1. 聊天输入栏点 `+` 能看到「小剧场」，打开后不跳页，直接出现类型和当前角色开关。
2. 当前角色开关和类型切换即时保存，再次打开仍保持；面板内不出现其他角色列表。
3. 选择类型不会自动打开当前角色的开关；行内状态同步显示「当前角色只聊天 / 会带 X 小剧场」。
4. 小剧场 App、聊天设置页里的旧入口仍可使用，不重复维护数据。
5. 弹窗在默认、frost、像素小兔主题及日夜模式下正常，无横向溢出。
6. 打开小剧场开关后，调试栏能看到来源为「小剧场」的 system 消息，位置在预设条目之后、最后一条聊天之前。
7. 切换类型后，请求里的写作要求切换；旧类型条目不受影响。
8. 小剧场 App 可按类型筛选，旧条目显示日常。
9. 四个类型各有不同详情页；NSFW 未确认前不显示正文。
10. 详情页在三套主题、日夜模式下正常，无横向溢出。
11. `node scripts/check.mjs`、`node scripts/test-context.mjs`、`python scripts/build_preview.py` 通过。
